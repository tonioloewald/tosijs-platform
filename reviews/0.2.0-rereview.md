## Major (confirmed; fix or document before the tag)

**M1. A /docs batch can commit two documents with the same `unique` value.** (correctness, confirmed; security reported the same issue as a minor). Location: `functions/src/docs.ts:333-346` (`commitWriteSet`).
- Phase 1 runs `isUnique` for each write as `tx.get(query)` against committed state. A Firestore transaction cannot see its own buffered writes, and every `tx.set` happens in phase 2.
- Example: `writes:[{p:'post/a',data:{path:'x'}},{p:'post/b',data:{path:'x'}}]`. Both writes pass and both commit, with no error. After that, lookups by `post/path=x` and blog routing are ambiguous. The same applies to role and module `name`.
- `validateWriteSet` de-duplicates only `p`, the document path.
- This contradicts the inline comment. It also contradicts BETA.md:328, which says a batch refuses "with the same codes and statuses as /doc".
- The bug predates this diff. virta writes through the batch path.
- **Fix:** in `commitWriteSet`, keep a Set of `parent\0field\0value` values claimed by earlier writes in the batch. Refuse a repeat with `unique` (400, via `rejectionStatus`) before phase 2. Add a unit or emulator test: two same-value writes in one batch return 400 `unique`, and nothing is written.
- **Minimum if deferred:** state the limitation in BETA.md's batch section and in the CHANGELOG.

## Follow-ups by destination

### This repo: `TODO.md` (correctness / efficiency / dryness / docs / coverage / dx)

- [ ] **Batch afterWrite fan-out** (efficiency, confirmed minor). Location: `functions/src/docs.ts:~401`.
  - Each committed write runs `await config.afterWrite(...)` serially before the response. For a 100-post batch, that is 100 serial `setRecord('config', …, 'blog-cache')` writes.
  - Fix: call idempotent, argument-free hooks such as clearBlogCache once per batch, for example with a `batchable` flag. At minimum, use `Promise.allSettled`.
  - Test: a 3-post batch calls clearBlogCache a bounded number of times.
- [ ] **Two uniqueness query implementations** (blast-radius, confirmed minor).
  - `doc.ts:178` uses `getRef(logical)`, which resolves `field=value` segments, and excludes self by id. `docs.ts:334` uses `physicalPath(...).slice(0,-1)` and excludes self by `ref.path`.
  - Fix: extract one `uniqueQuery(physicalDocPath, field, value)` helper that returns the query plus a self-exclusion predicate. /doc runs it with `.get()` and /docs with `tx.get()`.
  - Delete the redundant scalar guard at `doc.ts:185`. Otherwise record a keep-decision in DECISIONS.md.
- [ ] **Rate limit can be bypassed with X-Forwarded-For** (security, confirmed minor, latent since a8589d2). Location: `functions/src/utilities.ts:110`.
  - Key on the trusted, rightmost-hop IP (or `req.ip` with the correct trust-proxy hop count), and cap the size of `rateLimitMap`.
  - Test: rotating the X-Forwarded-For header does not reset the count.
  - If you choose not to fix it, reword BETA.md's "100 requests/minute per IP" contract.
- [ ] **(unverified) The batch parent-path fix has no test.** Location: `functions/src/docs.ts:338`.
