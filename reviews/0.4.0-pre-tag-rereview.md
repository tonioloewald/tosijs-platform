## Follow-ups by destination

### This repo: fix now or file to `TODO.md`

**Verified minors, correctness and security first**

- [ ] **Live-proposal cap is an anonymous lockout lever (security, correctness and blast radius; verified; three findings merged).** `endpoint.ts:319-320` counts every proposal with `expiresAt >= now`, whatever its status and whoever sent it, and proposing needs no credentials.
  - 20 anonymous POSTs, repeated every 10 minutes, make every legitimate `propose` return 429 indefinitely. That is about 2 requests a minute against a 100/min limiter.
  - Denied, installed and refused proposals hold their slot until expiry, so the owner cannot clear the queue. 21 legitimate installs in 10 minutes are refused.
  - The 429 text says "awaiting a decision", which is not what the query counts.
  - Direct `POST /install` with a configurator token is unaffected, and proposals stay inert, so integrity is not at risk.
  - Fix: count only `status == 'pending'` (or delete on decide), and exempt authenticated proposers.
  - Fix: make the 429 body and `scripts/install-manifest.js` name the token path.
  - A per-source bound is the only thing that stops an attacker refilling the slots.
  - **Owner decision needed:** whether the lockout is an accepted price for the storage bound in 0.4.0. If it is, record it in DECISIONS.md and BETA.md.
- [ ] **Sweep can delete a proposal whose approval is in flight (blast radius, correctness and security; verified; three findings merged).** `endpoint.ts:312-317` sweeps on `expiresAt` alone.
  - An approve taken seconds before expiry stays `deciding` across two `runInstall` calls.
  - A concurrent propose deletes the document, the outcome `update()` throws NOT_FOUND, and the browser gets 500 "install failed" although the install committed.
  - The verifier narrowed two points. The CLI misreport happens at expiry regardless of the sweep. An attacker cannot widen the window, only make a sweep inside it near-certain.
  - Fix: skip `deciding` in the sweep or add a grace period, and treat NOT_FOUND on the outcome write as non-fatal so the real result is returned.
