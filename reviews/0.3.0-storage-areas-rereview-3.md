## Major (non-blocking)

**M1. The Hosting sandbox CSP overrides the function's type-aware policy (verified: plausible; severity uncertain).** Files: `firebase.json:84`, `functions/src/blob-handler.ts:92-100`.
- Hosting replaces a function's CSP (the report shows this live). So on the site origin, every **streamed** `/blob` and `/stored` response gets `sandbox; default-src 'none'; img-src 'self' data:; media-src 'self'; style-src 'unsafe-inline'`, whatever its type.
- As a result, the INERT exemption in `deliveryHeaders` (PDF, audio, video, text, json) and its tests do nothing on the site origin.
- The two CSP strings already differ (`img-src data:` vs `img-src 'self' data:; media-src 'self'`).
- BETA.md and CHANGELOG tell hosts to hand-copy the rule into their own firebase.json.
- The signed-URL redirect path is not affected. Security is not weakened: the result is stricter than intended.
- Merged into this finding: the correctness **confirmed** minor (PDF plus BETA.md self-contradiction), the correctness unverified minor (two drifting copies) and the security unverified nit (PDF).
- User-visible symptom: Chromium probably refuses to render a PDF under a `CSP: sandbox` response. The documented example `/stored/public/document.pdf` and `/stored/blog/Character Sheet.pdf` would show as blocked. This is not yet checked in a browser.
- Fix, choosing one on purpose:
  - (a) Narrow the site-wide CSP `source` to exclude `/blob/**` and `/stored/**`. The function's `deliveryHeaders` then becomes the only policy. Add a test that the site-wide rule does not match those paths, and extend verify-blob check 7 with a PDF or PNG.
  - (b) Keep a blanket sandbox. Record that as a keep-decision in DECISIONS.md, remove PDF, audio and video from INERT so the two copies agree, export the CSP constant, and assert that Hosting's value equals it.
  - Either way, fix the contradiction in BETA.md.

## Minor / nit (non-blocking; unverified unless noted)

- **G1 timing fix is incomplete (unverified; correctness and security, merged).** `functions/src/blob-handler.ts:279`. A non-reader's *miss* awaits `deps.objects.delete(oldKey)`, but a *hit* skips it, so latency still reveals whether the guess matched (the tell is inverted, not removed). The new test counts only `put` calls, so its name claims more than it checks. Re-review 2 asked for exactly this fix.
- **The /stored allowlist has no handler-level test (unverified; security and correctness, merged).** `functions/src/stored.ts:61`. Only the pure `legacyObjectPath` is tested. If stored.ts reverted to `match[1]`, `bun test` would stay green. verify-blob check 16 asserts 404 with no positive control, so it cannot tell "refused" from "wrong bucket" (the exact appspot.com bug). Check 7 passes silently on a 302.
- **The stored.ts header comment teaches the B1 misconception (unverified; security, blast-radius and correctness, merged).** `functions/src/stored.ts:7-8, 22-23`. It says "served based on storage.rules – all files publicly readable" and gives `/stored/images/photo.jpg` as an example, which now returns 404.
- **Percent-decoding regression in /stored (unverified nit).** `functions/src/legacy-storage.ts:27`. Names containing a literal `%` (which `pathToStoredUrl` does not encode) now return 404. The `?query` part of `req.url` also gets decoded into the object name.
- **`objectKey` does not enforce that it stays disjoint from legacy folders (unverified nit).** `functions/src/blob-handler.ts:43`. Today three separate pieces of code keep area keys from starting with `blog/`, `public/` or `users/`, and nothing states that as one rule.
- **No bundle-size delta in the build output (unverified nit, efficiency).** `package.json:34`. This predates the diff.

No red or skipped tests were reported. The integration tests are still skip-guarded unless emulators run (see CLAUDE.md), and the storage-rules emulator test is still deferred (#2485).
