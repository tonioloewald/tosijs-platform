## Blockers

### B1 — Proofread Save silently commits the un-reviewed AI rewrite over the author's text
`src/blog.ts:1213` · correctness · **confirmed** · new in this diff

`openProofreadDiff` sets `source.value = revised` (the full Gemini revision) *before* `showDiff(true)`, and the only copy of the author's text is the private `#proofBefore`. The old implementation was a `position:fixed; inset:0` modal on `document.body`; the new in-place overlay renders inside `<tosi-code>`'s shadow (`[part="diffHost"]` is `position:absolute; inset:0`) and covers **only the editor** — the tab strip and the editor menu (Proofread / Save / Close) stay live.

Three live paths, all silent:
- **Save** → `savePost` does `blog.editorPost.content.value = source.value` and PUTs the entire AI rewrite, discarding every hunk the author was about to reject, with a success toast.
- **Preview tab** → `tabChanged` does the same assignment (recoverable — the diff stays open).
- **Proofread a second time** → `#proofBefore` is overwritten with the AI text, so Cancel now "restores" the model's revision as the author's own. Unrecoverable. Same for **Close**, which persists the revision to `localStorage` and destroys `#proofBefore`.

**Fix:** gate on an explicit `#proofOpen` state — `savePost`, `closeEditor`, `tabChanged`, `convertToMarkdown`, `summarize`, `proofread` no-op (or prompt) while set, and disable those menu items. Cheapest correct variant: keep the author's text in `source.value` and put the revision on `source.original`, inverting the label mapping — then a stray Save commits the author's own words.

### B2 — The release's headline fix is wired into only one of two mutation paths
`functions/src/doc.ts:451` (present) vs `functions/src/doc.ts:373` (absent) · correctness

`config.afterWrite` is invoked after `ref.set(data)` in the POST/PUT/PATCH branch. The DELETE branch (`await ref.delete()`) never calls it — verified: `afterWrite` has exactly one call site in `doc.ts`. So **deleting a blog post still leaves the blog cache stale for up to 24h**, which is precisely the bug commit `3b7dfdd` set out to close. `after-write.test.ts` exercises only the write methods, so the oracle cannot see the hole.

Shipping a fix that works for edits but not deletions is worse than not shipping it — it reads as solved.

**Fix:** call `config.afterWrite` after a successful `ref.delete()` (same try/catch-and-warn shape), and add a DELETE case to `after-write.test.ts`. See also F2 — neither call site has a test that fails without it.

### B3 — The demo `test` collection grants unauthenticated write, delete and list on production Firestore
`functions/src/collections/index.ts:5` · security · **empirically confirmed against production**

`COLLECTIONS.test` is registered unconditionally with `access: { [ROLES.public]: { read, list: ALL, write: ALL } }`. `accessMap` maps POST/PUT/PATCH/**DELETE** → `write`, and `getMethodAccess` seeds from the `public` entry before any role loop, so a caller with **no token** gets it. There is no schema, so document shape is arbitrary up to Firestore's 1 MB limit; `unique:['unique']` is satisfied by any string.

Live probe (unauthenticated, GET only): `GET .../docs?p=test` → **200** with real documents, including pre-existing junk from 2024. Control `?p=nosuchcollection` → denied.

Unauthenticated write/storage/invocation billing abuse on the production project, and an attacker-controlled document store inside the same database as `role`, `config` and `post`. No consumer exists anywhere in the repo.

**Pre-existing** (unchanged since `a8589d2`), so this does not gate the *diff* — but it gates the *deploy*, and it is a one-line fix. Delete the `test` entry or gate it on `process.env.FUNCTIONS_EMULATOR === 'true'`, then purge the existing `test` documents. Can ship as an independent hotfix ahead of the release if you prefer to unblock the rest.
