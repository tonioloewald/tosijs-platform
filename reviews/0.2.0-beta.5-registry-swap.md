## Blockers

### B1. The seeded `post` derive rewrites supplied paths on every edit (correctness, confirmed, blocker)
`functions/src/collections/seed-configs.ts:57` together with `functions/src/install/compile.ts:176-184`.
- **The mismatch:** `derive: [{op:'slug', to:'path', from:'title', when:'absent'}]` still runs `slugify(current)` when a path is present. That strips leading and trailing `-`, drops `_`, and truncates to 80 characters. Compiled `blog.ts:174-176` only generates a path when `!data.path`.
- **When it runs:** derive runs in `validate` on every PUT and PATCH after the merge.
- **Impact:** 96 of 791 published posts have paths that would change. Examples: `what-s-in-a-name-`, and an 86-character path that would be truncated. Each changes silently on its next save, which breaks `/blog/<old>`, inbound links and SEO. If the normalised path collides with another post's, the save fails the unique check instead.
- **Why the tests missed it:** `equivalence.test.ts:157-168` asserts the divergent behaviour, and its comment ("blog.ts slugifies whatever the author typed too") is false.
- **Fix:** make `when:'absent'` mean "only when absent", or add a generate-only slug mode. Correct the test and its comment. Add a parity fixture that PUTs a legacy post (trailing `-`, >80 characters) through both the compiled and the seeded `validate` and asserts the path is unchanged. Re-run `seed-registry.js --alias sandbox`.
- **Re-review scope:** correctness plus blast-radius over the remediation diff. The derive semantics in `compile.ts` also affect installed libraries that declare `slug`.

### B2. The seed opens `post/comment`, which compiled code denies (correctness + security, confirmed, major; must fix before the production seed)
`functions/src/collections/seed-configs.ts:227-237`.
- **What changes:** compiled `COLLECTIONS` never registers `post/comment`; the only occurrence is the doc-comment example in `access.ts:128`. The seed grants the public `read/list: ALL` and admin `read/write/list: ALL` with `schema:{type:'object'}`. With the switch on, the public can list every comment subcollection, and an admin can write schemaless, publicly readable documents there. The item is already stored on the sandbox.
- **Why the tests missed it:**
  - The `comparable` list in `seed-configs.test.ts:84` omits `post/comment`.
  - `seed-parity.isolated.ts` only covers post and page.
  - The uniqueness loop skips it silently (`if (!shipped) continue`).
  - `blockers.test.ts:80` allowlists it for public list.
- **Reverse gap:** `token` is compiled but not seeded. It is harmless (deny either way) and goes on the allowlist.
- **Fix:**
  - Drop `post/comment` from `PLATFORM_CONFIGS`, or make opening it a recorded owner decision and register it in compiled code too.
  - Hand-delete `system:registry/post~comment` on the sandbox, because seed-registry never deletes.
  - Add a two-way name-set parity test (seed names == compiled keys, with a commented allowlist for `token` and the emulator-only `test`).
  - Remove `post/comment` from `PUBLIC_LIST_ALLOWED` unless it is deliberately opened.
- **Re-review scope:** correctness plus security over the seed diff and the parity tests.

No cycle flag: the slug derive in `compile.ts` and the seed configs are new in this cycle, not the remediation of a prior blocker, and no lens has blocked twice.

- [ ] **Epoch race: stale rules tagged with the new epoch** (correctness/security/efficiency; confirmed by security and efficiency, the correctness report is unverified, merged). `registry.ts:226`.
  - **Ordering:** `reload()` reads the epoch after `load()`. A commit that lands mid-load leaves the old rules marked as current until the next TTL.
  - **Shared `inFlight`:** a post-change request can join a background load that started before the change, and CPU throttling after the response can widen the window.
  - **Stale reload after `invalidate()`:** `invalidate()` does not clear `inFlight`.
  - **Fix:** read the epoch before `load()`, or take it from the same `system:registry` get. Make `invalidate()` clear `inFlight` or use a generation counter, and don't let the post-change path join a background load. Add a test where the epoch changes between `load` and `epoch`. Fix or delete the comment "a revocation is never served stale" (`registry.ts:~193`).
