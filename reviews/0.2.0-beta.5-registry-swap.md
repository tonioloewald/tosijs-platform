## Blockers

### B1. The seeded `post` derive rewrites supplied paths on every edit (correctness, confirmed, blocker)
`functions/src/collections/seed-configs.ts:57` together with `functions/src/install/compile.ts:176-184`.
- **The mismatch:** `derive: [{op:'slug', to:'path', from:'title', when:'absent'}]` still runs `slugify(current)` when a path is present. That strips leading and trailing `-`, drops `_`, and truncates to 80 characters. Compiled `blog.ts:174-176` only generates a path when `!data.path`.
- **When it runs:** derive runs in `validate` on every PUT and PATCH after the merge.
- **Impact:** 96 of 791 published posts have paths that would change. Examples: `what-s-in-a-name-`, and an 86-character path that would be truncated. Each changes silently on its next save, which breaks `/blog/<old>`, inbound links and SEO. If the normalised path collides with another post's, the save fails the unique check instead.
- **Why the tests missed it:** `equivalence.test.ts:157-168` asserts the divergent behaviour, and its comment ("blog.ts slugifies whatever the author typed too") is false.
- **Fix:** make `when:'absent'` mean "only when absent", or add a generate-only slug mode. Correct the test and its comment. Add a parity fixture that PUTs a legacy post (trailing `-`, >80 characters) through both the compiled and the seeded `validate` and asserts the path is unchanged. Re-run `seed-registry.js --alias sandbox`.
- **Re-review scope:** correctness plus blast-radius over the remediation diff. The derive semantics in `compile.ts` also affect installed libraries that declare `slug`.

### B2. The seed opens `post/comment`, which compiled code denies (correctness + security, confirmed, major; must fix before the production seed)
`functions/src/collections/seed-configs.ts:227-237`.
- **What changes:** compiled `COLLECTIONS` never registers `post/comment`; the only occurrence is the doc-comment example in `access.ts:128`. The seed grants the public `read/list: ALL` and admin `read/write/list: ALL` with `schema:{type:'object'}`. With the switch on, the public can list every comment subcollection, and an admin can write schemaless, publicly readable documents there. The item is already stored on the sandbox.
- **Why the tests missed it:**
  - The `comparable` list in `seed-configs.test.ts:84` omits `post/comment`.
  - `seed-parity.isolated.ts` only covers post and page.
  - The uniqueness loop skips it silently (`if (!shipped) continue`).
  - `blockers.test.ts:80` allowlists it for public list.
- **Reverse gap:** `token` is compiled but not seeded. It is harmless (deny either way) and goes on the allowlist.
- **Fix:**
  - Drop `post/comment` from `PLATFORM_CONFIGS`, or make opening it a recorded owner decision and register it in compiled code too.
  - Hand-delete `system:registry/post~comment` on the sandbox, because seed-registry never deletes.
  - Add a two-way name-set parity test (seed names == compiled keys, with a commented allowlist for `token` and the emulator-only `test`).
  - Remove `post/comment` from `PUBLIC_LIST_ALLOWED` unless it is deliberately opened.
- **Re-review scope:** correctness plus security over the seed diff and the parity tests.

## Majors (confirmed; not release-blocking at this patch, but gated as noted)

### M1. The registry race fix creates a thundering herd after an epoch change or epoch read failure (correctness + blast-radius, confirmed)
`functions/src/collections/registry.ts:180` (also the epoch-failure branch at ~185, and ~201/207/212)

`reload({fresh:true})` bumps `generation` and nulls `inFlight`, but leaves the old snapshot in place, with its old epoch and old `checkedAt`. Every request that checks concurrently then starts its own fresh load, which makes the previous load stale, so that load never stores its result.

- **Measured:** a scratch probe did 40 loads for 40 requests at HEAD; the same probe did 2 on d7e2ca4. Prod-clone loads take about 300–950 ms.
- **Impact:** liveness and cost only. Each request still returns fresh rules, so revocation is correct. During a Firestore brown-out, every request that arrives inside each check window does a full inline load and compile, adding Firestore reads just when Firestore is already struggling.
- **Stale window:** requests within epochTtl of the old `checkedAt` are still served the old rules after another request on the same instance has seen the change.
- **Reach:** with the switch off, only namespaced-library requests (for example, consumer hosts like virta) are affected. That still makes this a live regression in shipping code. With the switch on, every platform request is affected.
- **Fix:** on an observed epoch change or epoch read failure, bump the generation, **set `this.snapshot = null`**, then reload. Later requests will join the single fresh in-flight load. Alternatively, tag `inFlight` with the generation or epoch it started under.
- **Test:** add a regression test that a burst after an epoch change does at most 1–2 loads and that the stored snapshot carries the new epoch.
- **Re-review scope:** correctness + security over `registry.ts` only.

### M2. B1 is not fixed end to end: `savePost` re-slugifies the stored path on every save (correctness, confirmed; predates this release)
`src/blog.ts:1059`

This line sends every saved path through `slugify`, including an unchanged stored path:

`data.path = typedSlug ? slugify(typedSlug) : slugify(title)`

`slugify` trims `-`, maps `_` to `-` and truncates to 80 characters. The server now stores supplied paths verbatim, so opening `what-s-in-a-name-` and saving it without changes moves its URL. This is the same impact as B1: 96 of 791 posts would get broken `/blog/<old>` links and lose SEO, or hit a unique-check collision. It happens in production today regardless of the switch.

The new tests don't catch it: the seed-parity legacy fixture only exercises server `validate`, and `blog-pure.test.ts` tests `slugify` alone.

- **Fix:** slugify only when the path is empty, or when the author changed it from the stored value.
- **Test:** saving a post with a legacy path (trailing `-`, `_`, more than 80 characters) sends the path unchanged.
- **Scheduling:** the client code is moving to tosijs-blog, but it is live now. The owner decides whether to fix it here or track it separately. Either way, B1 must not be reported as fully closed.
- **Re-review scope:** correctness over `savePost` only.
