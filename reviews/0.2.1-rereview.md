## Blocker

### B1. The "curated when owned" rule publishes the claiming operator's email (`_by.name` and `derive:principal`) (verified, confirmed)
Files: `functions/src/collections/roles.ts:121`, `functions/src/claim.ts:186-193`. This single entry merges the correctness, security and blast-radius findings.

- **Mechanism:**
  1. When the claimer has no role doc yet, `/claim` creates one with `name: user.email ?? user.uid` and `userIds: [user.uid]`.
  2. `getUserRoles` sets `principal = {uid, name: credentialName(user)}`, and the join sets `name = docs[0].name`, which is the email.
  3. In `principalIdentity`, `soleOwner` is true, so it returns `name = docName ?? principal.name`. The email wins even when the credential has a display name.
- **Where the email ends up:**
  - `provenanceOf` stamps it into `_by.name` (write-pipeline.ts).
  - `compile.ts` passes it to `derive:{op:'principal', field:'name'}`.
  - Agent-token writes by the same owner resolve to the same name.
  - Nothing strips `_by` on read, so it reaches the public through `/doc`, `/docs`, `/cachedQuery` and SSR.
- **Who is affected:** the first human on every provisioned host, via the documented claim ceremony. The sandbox, virta and loewald.com were claimed this way and already hold role docs named with an email.
- **Severity note:** the verifiers disagreed on the rating. Correctness kept it as a blocker. Security and blast-radius adjusted it to major because v0.2.0 already published `userRoles.name`, which was the email, for claimed owners. The "worse than before" argument holds only against the unreleased intermediate commit f6a6122. It still blocks because:
  - 0.2.1's whole purpose is B2. The CHANGELOG says (CHANGELOG.md:25): "Never an email address, because `_by` is published with public documents". That is false for the most common owner on every host.
  - It is unresolved security/correctness in the remediated code.
- **Tests:** none. Every sole-owner test uses a non-email name such as "Curated Name".
- **Fix (small):**
  1. **Enforce the rule where `_by` is produced.** `principalIdentity` should drop any candidate name, whether it comes from the doc or the credential, that contains `@` or equals one of `userRoles.contacts`' values, then fall back to `principal.name` or no name. This also covers role docs that already exist on deployed hosts without a migration.
  2. **Fix the source.** `claim.ts` should write `name: credentialName(user) ?? user.uid`, or leave the name unset.
  3. **Tests:**
     - A sole owner whose doc name is an email and whose credential name is "Ada" gets `_by.name === 'Ada'`.
     - With no credential name, `_by.name` is absent.
     - The same two cases for `derive:principal`.
     - One test that goes through claim → `getUserRoles` → write.
  4. **CHANGELOG.** Keep the "never an email" line accurate. Add an "Action required" note for hosts that already have email-named role docs, and optionally have `scripts/audit-host.js` flag them.
  5. **Other writers.** Check that no other role-doc writer (provision-sandbox, seed scripts) sets an email as the name.
- **Re-review scope:** correctness + security + blast-radius over the remediation diff only: `roles.ts` principalIdentity, `claim.ts`, the new tests, the CHANGELOG wording, and `audit-host.js` if it is touched.
