## Blockers

### B1: The release version is inconsistent. `package.json:3` (confirmed)
The working tree has three uncommitted files that disagree:
- `package.json` is at **0.2.0**, not a prerelease.
- The CHANGELOG heading is `## 0.2.0 — 2026-09-26 (draft)`, but its body says "the first beta on npm since 0.2.0-beta.2".
- The README banner says **0.2.0-beta.6**.

In `publish.yml`, the meta step (around lines 92-120) gives any version without a `-` the dist-tag `latest`. Tagging v0.2.0 would therefore stage 0.2.0 under `latest`. One 2FA approval would then move `latest` off 0.1.0, which goes against the plan (dist-tag beta, `latest` stays at 0.1.0), and would permanently use up the 0.2.0 version number. release-doctor's changelog gate (`cl.includes(version)`, release-doctor.ts:253) passes on the existing "0.2.0-beta.5" text, so Tier 0 gives a pass that looks right but is wrong.
**Fix:**
- Set package.json to `0.2.0-beta.6`.
- Change the CHANGELOG heading to `## 0.2.0-beta.6 — 2026-09-26` and drop "(draft)".
- Keep the README banner at beta.6.
- Commit, then run a new dry run and confirm the output says `dist_tag=beta`.

**Re-review scope:** Tier 0, plus a person checking the dist-tag.

### M1 (security + correctness + blast-radius, merged): an unlocked `npm install` with scripts runs inside the id-token job. `.github/workflows/publish.yml:132-133` (confirmed)
- `install:ci` is `cd functions && npm install --no-audit --no-fund`.
- `functions/package-lock.json` is gitignored and there is no `--ignore-scripts`.
- It runs in the single `publish` job, which has `id-token: write`, **before** Build, Pack and Stage.

As a result, every dependency of firebase-admin, firebase-functions and eslint is resolved fresh on each publish, and every one of their install scripts runs. A compromised package could patch root `node_modules/typescript` or `dist-lib` and poison the tarball the workflow packs, and dist-lib contains the RBAC kernel (access.ts, write-pipeline.ts). Nothing downstream catches this:
- dist-lib is gitignored, so the Build check compares nothing (see m6).
- The job has no attestation file.
- The Verify step only proves that the registry bytes equal the bytes this run built.
- The 2FA approval shows the approver a version number, not the file contents.

The previous template ran only `bun install --frozen-lockfile`, which is locked and runs no untrusted scripts. So this release adds the exposure. Build and Pack do not need `functions/node_modules`.
**Fix for this release:**
- Add `--ignore-scripts` to `install:ci` and confirm the functions test lane stays green.
- Or move the `releaseDoctor.install` step to after Pack.

The structural fix, a separate job for the id-token, is listed under shared practices.
